Project Overview

Project Objective

The objective of CRACKA NIDS is to develop a Network Intrusion Detection System that uses Machine Learning to identify and classify network traffic. The system uses the NSL-KDD dataset for model development and Scapy for live network packet capture and analysis.

Project Scope

  • NSL-KDD based network intrusion classification.
  • Random Forest based Machine Learning prediction.
  • Manual traffic prediction.
  • Batch CSV traffic analysis.
  • Live network packet prediction using Scapy.
  • MySQL based user and prediction history management.

Technology Stack

CRACKA NIDS combines Machine Learning, Python web development, packet analysis and database management to provide a complete intrusion detection workflow.

Python & Machine Learning

Python is used as the primary programming language. NumPy and pandas are used for data processing, while scikit-learn is used for preprocessing, model training and prediction.

Flask Backend

Flask manages application routes, authentication, manual prediction, batch prediction, live packet prediction and communication between the frontend and Machine Learning model.

Scapy

Scapy is used in the live prediction module to capture network packets, extract packet information and construct the required features for Machine Learning prediction.

MySQL Database

MySQL is used to store user information and prediction history. Packet prediction records are associated with the logged-in user and can be viewed through the History Logs page.

Core System Modules

The system is divided into four major modules that together implement the complete Network Intrusion Detection workflow.

1. Data Preprocessing

The NSL-KDD training and testing datasets are loaded and prepared for Machine Learning. Attack names are grouped into five classes: Normal, DoS, Probe, U2R and R2L. Categorical features including protocol type, service and flag are encoded using LabelEncoder. The numerical feature set is standardized using StandardScaler.

2. Model Training

The preprocessed data is used to train a Random Forest classifier. The trained model is evaluated using test data and the required Machine Learning artifacts are saved for later prediction.

3. Flask Backend

Flask provides the central application backend. It handles authentication, page rendering, manual prediction, batch CSV prediction, live packet prediction and history management.

4. Frontend Interface

The frontend provides a web-based interface through which users can access the dashboard, project overview, manual prediction, live prediction, model description and prediction history.

Dataset & Machine Learning Model

NSL-KDD Dataset

The project uses the NSL-KDD dataset as the source of network traffic records for Machine Learning. The dataset contains network connection features and attack labels used to train and evaluate the intrusion detection model.

41 Feature Representation

Network records are represented using the NSL-KDD feature structure. Categorical fields are encoded and the resulting feature vector is scaled before being provided to the model.

Random Forest

The current implementation uses Random Forest as the primary classification model. The classifier predicts one of the five supported traffic categories.

Prediction Classes

Normal DoS Probe U2R R2L

Prediction Modes

The system provides three different methods for analyzing network traffic.

Manual Prediction

Users can enter selected network traffic values such as duration, protocol type, service, flag, source bytes, destination bytes and failed logins. The backend converts the input into the required feature representation and performs prediction.

Batch CSV Prediction

Users can upload a CSV file containing network traffic records. The system processes the records and generates a prediction and confidence value for each input record.

Live Network Prediction

The live prediction module uses Scapy to capture network packets. Packet information is extracted and converted into features before being passed to the trained Random Forest model.

Prediction History

Live prediction sessions can be saved as sessions in MySQL. Users can view their previous prediction records through the History Logs page.

Attack Categories

The trained system uses five output categories for network traffic classification.

Normal

Represents legitimate network traffic that is classified as non-intrusive.

DoS

Represents Denial of Service related attack traffic.

Probe

Represents network probing and scanning related traffic.

U2R

Represents the User-to-Root attack category.

R2L

Represents the Remote-to-Local attack category.

System Workflow Summary

  1. User registers or logs into the CRACKA NIDS application.
  2. The user selects manual prediction, batch CSV analysis or live packet prediction.
  3. The Flask backend receives and validates the request.
  4. Input data is converted into the required feature representation.
  5. The saved scaler and label encoders are used during preprocessing.
  6. The Random Forest model performs the classification.
  7. The system generates the predicted class and confidence value.
  8. The result is displayed through the frontend interface.
  9. Live prediction sessions can be saved in the MySQL packet history.

Project Result

CRACKA NIDS provides a complete Machine Learning based network intrusion detection workflow. It combines NSL-KDD based model training, Random Forest classification, Flask web services, Scapy-based live packet analysis and MySQL based history management in a single web application.
