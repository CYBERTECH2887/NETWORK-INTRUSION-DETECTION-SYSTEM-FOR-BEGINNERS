Project overview

A Network Intrusion Detection System built as a minor project at Govt. Polytechnic Bhagalpur.

Objective

Classify network traffic as normal or as one of four attack types using machine learning and deep learning. Models are trained on the NSL-KDD dataset, and Scapy supplies live packets for real-time checks.

What is included

  • Random Forest and neural network ensemble using soft voting
  • Manual prediction from a short form
  • Batch analysis of CSV traffic files
  • Live packet capture with sound and desktop alerts
  • User accounts with hashed passwords and per-user history in MySQL

How a packet becomes a verdict

Every prediction path follows the same steps.

CaptureScapy reads packets for one second, or a CSV row is read.
Build featuresThe 41 NSL-KDD features are filled in.
Encode and scaleText fields become numbers, then all values are standardised.
ScoreRandom Forest and the neural network each give class probabilities.
VoteProbabilities are averaged and the 40% attack threshold is applied.
ReportThe result is shown, alerts fire, and sessions are saved.

Core system modules

The system is divided into four major functional modules.

Module 1: Preprocessing & Training

Cleans and encodes NSL-KDD data, training the Random Forest and Deep Neural Network models.

Module 2: Frontend Interface

Responsive glassmorphism UI featuring dark/light modes, sound alerts, and desktop notifications.

Module 3: Flask Backend

Central backend handling routing, user authentication, and the soft-voting ensemble prediction logic.

Module 4: DBMS & Packet Sniffing

Manages user records and logs in MySQL while Scapy sniffs live packets for real-time analysis.

Technology

Python, TensorFlow, scikit-learn

Training, preprocessing and both models.

Flask

Routes, sign-in with Werkzeug hashing, and the prediction APIs.

Scapy

Live packet capture and feature building.

MySQL

Accounts and saved sessions.

Prediction classes

Normal

Legitimate traffic with no intrusion.

DoS

Denial of service: traffic floods meant to knock a service offline.

Probe

Scanning and surveillance to map open ports and services.

R2L

Remote to local: an outsider tries to gain access, for example by guessing passwords.

U2R

User to root: a normal account tries to gain administrator rights.
